## Overlaps resolved

- Which document holds the rules. Competing: `ce-code-review` (three file names at any depth, with one kind taking precedence, `project-standards-reviewer.md` 11), `pr-review-toolkit` (one named guidelines file) and brooks-lint (a configuration file in the root, `common.md` 21-27). None wins: the lane's own rule (first of `PROJECT_RULES.md`, `AGENTS.md`, `CLAUDE.md`, `CONTRIBUTING.md` in the root) replaces all three, keeping brooks-lint's root-only lookup and `ce-code-review`'s reading from the reviewed tree.
- Evidence for a breach. Competing: `ce-code-review` (59-64: "A finding without both a cited rule and a cited violation is not a finding. Drop it.") and `pr-review-toolkit` (`code-reviewer.md` 40: "Specific CLAUDE.md rule or bug explanation"). Winner: `ce-code-review`, tightened from citing to quoting word for word.
- What compliance means. Competing: project-rules adherence (`ce-code-review` project-standards persona) and control-framework compliance (`security-scanning-security-hardening` 111-115, `secrets-management`). Winner: project rules, as the lane defines the reviewer; the regulatory reading has no review-time mechanism in any source.
- Rule strength. Competing: brooks-lint severity overrides per rule (`common.md` 29-56) and security-and-hardening's three tiers (49-80). Winner: the three tiers, because a prose rules file states strength in words, not in a configuration key.
- Rule breach that is also a defect. Competing: `pr-review-toolkit`'s single reviewer for both rules and bugs (`code-reviewer.md` 14-20) and `ce-code-review`'s separate standards persona. Winner: separation; the breach is this reviewer's and the defect is the specialist's.
- Rules files below the root. Competing: `ce-code-review` (`scope.md` 137: candidates at any depth, a root file governs the whole checkout and a nested one only its own folder; a designated coding-standards file outranks instruction files for the files it governs) and the code-review command (`code-review.md` 12: the root file plus a file in each folder of a modified file). Winner: the folder-by-folder reading of both, with the lane's four names in a fixed order taken per directory; the coding-standards file is only a fallback after the four, because the order is the lane's own and a test checks it.
- How strong a middle confidence may be. Competing: `ce-code-review` persona (`project-standards-reviewer.md` 45: anchor 50 reaches the report only at P0) and the earlier version of this skill (never report 50). Winner: the source, so a rule the file marks as critical is reported at 50 when its application needs a judgement.
- Where a check about comments, documents or configuration belongs. Competing: the audit suite's comment, documentation and configuration auditors (they judge quality) and this reviewer (it judges breaches of written rules).
