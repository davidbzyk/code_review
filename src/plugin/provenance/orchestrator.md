## Overlaps resolved

- Who combines the findings. Competing: `thermos` (`thermos/SKILL.md` 19: deduplicate, weight overlapping findings more, settle disagreements "with your own judgment") and `ce-code-review` (`SKILL.md` 33, `finish-review.md` 27-29: the model merges only through a helper and treats each output as a claim). Winner: the `ce-code-review` direction, taken further: a bundled script merges by place, the validator checks claims, and the orchestrator judges nothing. Weighting by overlap is dropped (see the aggregator record).
- What the reviewers are handed. Competing: `thermos` (`thermo-nuclear-review-subagent.md` 8, 28: diff output and full file contents in the prompt, base defaulting to `main`) and `ce-code-review` (`dispatch-reviewers.md` 34: pass paths, not contents). Winner: `ce-code-review`, carried to its end: two refs and an optional file list, so every reviewer reads the same repository for itself and no base is ever assumed.
- Order of work. Competing: `multi-agent-review` (82-101: some lenses run after others, and shared context passes between agents) and `ce-code-review` plus `thermos` (all reviewers at once, none fed another's output). Winner: all at once; the same file's own best practice "maintain agent independence" (201) contradicts its context-passing idea, and independence is what keeps one reviewer's mistake from becoming seven.
- A start that is refused. Competing: this project's rule that a failed reviewer is not retried, and `ce-code-review` (`dispatch-reviewers.md` 59: capacity errors are back-pressure and are retried, other failures are recorded). Winner: both, split by cause: a refusal for too many running agents is retried when another finishes, and a run that started and failed is never retried.
- Asking the user. Competing: `ce-code-review` (`SKILL.md` 38: never stop to ask), `brooks-lint` (`test-guide.md` 20-26: at most one question, then proceed) and the "Limitations" footer of two security sources (stop and ask when inputs are missing). Winner: `ce-code-review`; the run is unattended and a question would have no one to answer it. A failing command stops the run with its one-line error.
