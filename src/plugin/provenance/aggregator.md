Source paths are relative to `third_party/`. "Adapted" means the idea was taken and written again as code for this project's contract; the "What changed" column says how this version differs. "Cited" means the source was read and is acknowledged, but the code does something else. No source code is copied.

Behaviour of the code with no source in the mined plugins, which is this project's own: a finding's line range is recomputed from where its quote is found, and a claimed range is only a hint between two places the same quote occurs; a claim wider than thirty lines is never merged; a reviewer file credited to another reviewer, or written by an agent that never ran, is not accepted; git is run with an argument list, with replacement objects off and redirecting variables removed, and reviewer files that are links are not read; a decline that fits more than one finding removes none; `rebuild` recomputes a run from the reviewers' files and the validator's file alone for a party that does not trust the main agent; and `export_commit` writes a commit's files for a caller that cannot trust the repository later.

## Overlaps resolved

- Who merges. Competing: `ce-code-review` (`finish-review.md` 33: merge differently worded findings only when they describe the same defect and fix path, a judgement the orchestrator makes), `thermos` (`thermos/SKILL.md` 19: weigh by overlap, settle by own judgement) and this project (a script, by place). Winner: the script, because the main agent must not judge and a script cannot weigh meaning. The cost is real: two different defects at one place appear as one finding, and the loser is only named in `also_raised_by` (see the table of parts left out).
- Whether agreement counts. Competing: `thermos` (19: overlapping findings weigh more), `multi-agent-review` (163-172: per-lens weights) and `ce-code-review` (`findings-mechanics.py` 87-88, 128-131: one step up only when a verified cross-model peer agrees). Winner: `ce-code-review`, stricter, because every reviewer here is one model family.
- The confidence floor. Competing: `ce-code-review` (`subagent-template.md` 82 and `findings-mechanics.py` 218-251: below 75 is suppressed after the merge unless P0), `pr-review-toolkit` (`code-reviewer.md` 32: report at 80 or above on a 0-100 scale) and this project (50 by default, before the merge). Winner: this project, because the reviewer skills already say which findings may sit at `50`, so the floor only has to remove `0` and `25`.
- A finding with no quote. Competing: `ce-code-review` (`findings-mechanics.py` 124-127: lower to 50) and this project (drop). Winner: drop; the contract makes the quote mandatory, and the gate also sets the lines every later step acts on.
- An unproven finding at the validator. Competing: `ce-code-review` (`finish-review.md` 69: unresolved P0 and P1 stay in the report as labelled gates) and this project (no verdict leaves it in place, and the run is marked `partial`). Winner: this project, with the same visible result, since the contract has no per-finding validation field (see the table of parts left out).
- Which findings are validated. Competing: `ce-code-review` (`finish-review.md` 62: every P0 and P1 plus every actionable finding, minus those corroborated by a second model) and this project (every P0 and P1). Winner: this project; the contract has no action classes and no second model.
