## Overlaps resolved

- Security persona. Competing: `ce-code-review/references/personas/security-reviewer.md` (9-16) and `security/security-reviewer/SKILL.md` (12-16), which share the sentence "Trace the data from its entry point to the dangerous sink." Winner: the `ce-code-review` copy, because it has two more classes (feature-gate leaks, protections switched off) and uses the anchored confidence values. The standalone copy keeps one contribution, its explicit lowered floor.
- Weakness lists. Competing: `security/007/references/owasp-checklists.md` (three lists with a detection column), `security/security-and-hardening/SKILL.md` (process and worked examples) and `security/security-audit/SKILL.md` (184-201, category names only: "Injection (SQL, NoSQL, OS, LDAP)"). Winner for the classes: 007, for breadth and the LLM list. Winner for the method: security-and-hardening ("If you can't name the trust boundaries for a feature, you're not ready to secure it"). security-audit keeps its sweep order and quality gates.
- What is reportable on its own. Competing: security-and-hardening's always-do tier (51-60: set headers, set cookie flags) and the always-rejected rule on missing headers and cookie flags alone. Winner: the always-rejected rule, because a reviewer of a change needs an exploit path; a hardening item becomes a finding only when the change removes a protection that was there (`ce-code-review` persona, 16).
- Server-side fetch. Competing: security-and-hardening (198-229, allow-list, resolve, no redirects, check-to-connect gap), security-arsenal (133-149, how the check is defeated) and 007's injection scanner (444-484, call shapes). Winner: security-and-hardening for the bullet, because it describes the code; the other two confirm it.
- Secret handling in the finding itself. Competing: 007's scanner (409-422, redact to a few characters) and the contract (verbatim quote). Winner: the contract; the redaction idea survives as never repeating the value outside `quote`.
- Agent and LLM checks. Competing: 007 `ai-agent-security.md`, security-and-hardening (361-387) and 007's injection scanner (354-393, prompt built from user text). Winner: security-and-hardening's framing (output is untrusted, permissions enforced in code) with 007's tool-authority and budget detail; input pattern block-lists from 007 (300-312) are not taken, because they are weak controls and hold example attack text.
- Lock files. Competing: brooks-lint (`pr-review-guide.md` 10-12, skip generated files and lock files) and the dependency sources. Winner: the dependency sources; a lock-file change is a supply-chain change.
- Confidence scale. Competing: `ce-code-review` anchors (`subagent-template.md` 59-69: "Pick the single anchor whose criterion you can honestly self-apply"), `pr-review-toolkit` 0-100 bands (`code-reviewer.md` 24-32: "Only report issues with confidence >= 80"), `security/security-reviewer` float floor (18-26), `security/007` impact-by-probability matrix (`stride-pasta-guide.md` 389-395) and the brooks-lint strictness presets (`common.md` 210-221). Winner: the `ce-code-review` anchors, because they are the same five values as the contract and each has a behaviour the reviewer can check itself against; a continuous score invites false precision.
- Shape of a finding's explanation. Competing: `ce-code-review` (`subagent-template.md` 112: "Lead with observable behavior") and brooks-lint's Iron Law (`common.md` 9: "Symptom, Source, Consequence, Remedy"). Winner: the `ce-code-review` rule, because the contract has one `description` field and the reader needs the effect first; the brooks requirement that a consequence be stated is kept inside it.
- Scope of a review. Competing: `ce-code-review` tiers (`diff-scope.md` 41-53), thermos (`thermo-nuclear-review/SKILL.md` 15-18: "ONLY report issues related to code that is being ADDED or MODIFIED") and `pr-review-toolkit` (`code-reviewer.md` 12, unstaged diff by default). Winner: `ce-code-review`, because it alone says what to do with an untouched line the change breaks; thermos would drop it.
- Intended changes. Competing: `ce-code-review` (`subagent-template.md` 136: check comments and commit messages for intent) and thermos (`thermo-nuclear-review/SKILL.md` 35-36, the intended-breakage exemption with its limits). Winner: thermos, because it also says when the exemption stops applying.
- Division of labour. Competing: `multi-agent-review` (six lens names, 30-37), thermos (two remits, `thermos/SKILL.md` 16-18) and the `ce-code-review` adversarial persona (80-91, a per-owner list). Winner: the `ce-code-review` list as the model, because it names an owner for each kind of defect; the other two are cited.
