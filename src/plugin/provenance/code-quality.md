## Overlaps resolved

- Maintainability rubric. Competing: `ce-code-review` maintainability persona (conditions and severity map), thermos (27-32: reframe "so that whole branches, helpers, modes, conditionals, or layers disappear entirely") and brooks-lint R1 and R4 (numbers: "Function longer than 20 lines", "Nesting depth greater than 3 levels"). Winner: the `ce-code-review` conditions, because each says what must be visible in the change; thermos supplies the demand to name what would be deleted; the brooks-lint numbers are kept as prompts only.
- Whether to report quality at all. Competing: `ce-code-review` (`subagent-template.md` 141: complaints such as "this file is getting long" are subjective without a rule) and thermos and brooks-lint, which report them. Resolution: report only with a named cost and a concrete fix, and only at confidence 75 or 100; a limit the project has written down is the compliance reviewer's.
- File size. Competing: `ce-code-review` (14, P1 when a file crosses a thousand lines) and thermos (186, a presumptive blocker). Both agree on the signal. Severity follows this contract's scale instead, where P1 means a defect normal use will hit, so the finding is P2.
- Comments. Competing: `pr-review-toolkit` comment analyzer (accuracy, completeness, long-term value) and `ce-code-review` (17-18, restating comments and stale sibling claims). Winner: accuracy checks from the analyzer plus the two `ce-code-review` shapes; completeness is dropped because a missing comment cannot be quoted.
- Duplication. Competing: brooks-lint R3 (110-118), thermos (102, copy-pasted logic) and the maintainability persona's canonical-helper item (15). Split by reach: repetition inside the change or file is here; a duplicate of a helper elsewhere is the architecture reviewer's.
- Simplification advice. Competing: thermos (ambitious restructuring) and the `pr-review-toolkit` simplifier's counter-rules (65-70: do not "Prioritize \"fewer lines\" over readability"). Both kept: push for deletion of real complexity, never for compression.
- Confidence scale. Competing: `ce-code-review` anchors (`subagent-template.md` 59-69: "Pick the single anchor whose criterion you can honestly self-apply"), `pr-review-toolkit` 0-100 bands (`code-reviewer.md` 24-32: "Only report issues with confidence >= 80"), `security/security-reviewer` float floor (18-26), `security/007` impact-by-probability matrix (`stride-pasta-guide.md` 389-395) and the brooks-lint strictness presets (`common.md` 210-221). Winner: the `ce-code-review` anchors, because they are the same five values as the contract and each has a behaviour the reviewer can check itself against; a continuous score invites false precision.
- Shape of a finding's explanation. Competing: `ce-code-review` (`subagent-template.md` 112: "Lead with observable behavior") and brooks-lint's Iron Law (`common.md` 9: "Symptom, Source, Consequence, Remedy"). Winner: the `ce-code-review` rule, because the contract has one `description` field and the reader needs the effect first; the brooks requirement that a consequence be stated is kept inside it.
- Scope of a review. Competing: `ce-code-review` tiers (`diff-scope.md` 41-53), thermos (`thermo-nuclear-review/SKILL.md` 15-18: "ONLY report issues related to code that is being ADDED or MODIFIED") and `pr-review-toolkit` (`code-reviewer.md` 12, unstaged diff by default). Winner: `ce-code-review`, because it alone says what to do with an untouched line the change breaks; thermos would drop it.
- Intended changes. Competing: `ce-code-review` (`subagent-template.md` 136: check comments and commit messages for intent) and thermos (`thermo-nuclear-review/SKILL.md` 35-36, the intended-breakage exemption with its limits). Winner: thermos, because it also says when the exemption stops applying.
- Division of labour. Competing: `multi-agent-review` (six lens names, 30-37), thermos (two remits, `thermos/SKILL.md` 16-18) and the `ce-code-review` adversarial persona (80-91, a per-owner list). Winner: the `ce-code-review` list as the model, because it names an owner for each kind of defect; the other two are cited.
